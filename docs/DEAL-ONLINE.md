# 扫码发牌：组织者的准备工作

发身份有两种方式，**轮传**（一台设备沿桌传）什么都不用配、也不用网络，是默认那条路。这份文档只针对第二种 —— **扫码发牌**：你举着二维码，各人用自己手机扫，扫到即看到身份。

它需要一个**你自己的**数据库来给玩家排队（谁先扫到谁排前面）。原因是你的平板显示完二维码就可能被拿去干别的，它不能充当服务器。

准备一次，之后每局都能用。

---

## 一、为什么需要你自己准备

- **仓库里没有任何地址**。这个项目不带默认后端，代码、构建产物、CI 里都不存在任何数据库地址、API Key 或 token
- **地址只存在你的浏览器里**（`localStorage` 的 `bgtools:deal-online`），通过二维码的 fragment 传给玩家。项目作者拿不到，也不经过任何第三方
- 换句话说：**你的数据库只有你和当场扫码的人在用**

## 二、Firebase Realtime Database

免费档远远够用（一局约 235 字节）。

### 1. 建库

1. 打开 [Firebase 控制台](https://console.firebase.google.com/)，新建一个项目（不用开 Analytics）
2. 左侧 **Build → Realtime Database → Create Database**
3. 区域随便挑一个离桌子近的，初始规则选 **Locked mode**（下一步整份替换掉）
4. 记下页面顶部那条数据库 URL，形如 `https://<你的实例>.<区域>.firebasedatabase.app`

### 2. 发布规则

**Rules** 标签页，整份替换成下面这段，然后 **Publish**：

```json
{
  "rules": {
    "bgtools": {
      "deal": {
        "$gameId": {
          ".read": true,
          "claims": {
            "$rid": {
              ".write": "!data.exists() && $gameId.length === 12 && $rid.length === 12",
              ".validate": "newData.val() === now"
            }
          },
          "pool": {
            ".write": "!data.exists() && $gameId.length === 12",
            "$k": {
              ".validate": "$k.length <= 24 && newData.isString() && newData.val().length <= 64"
            }
          }
        }
      }
    }
  }
}
```

这份规则在管什么：

| | |
|---|---|
| `bgtools/deal` 之外的一切 | 默认拒绝，你库里别的数据不受影响 |
| 排队记录（`claims`） | 只能新建、不能改、不能删；值**只能是服务端时间**（客户端写死数字会被拒） |
| 内容池（`pool`） | 只能写一次，写完锁死；键 ≤ 24 字符、值必须是字符串且 ≤ 64 字符（**按字符算，不是字节** —— 64 个汉字也写得进）。目前只有冒牌艺术家用它：艺术家身份对应词、冒牌货对应主题 |
| id 长度 | 牌局 id 与玩家 id 都必须是 12 字符，挡掉乱写路径 |
| 读 | 只有**具体某一局**可读。`deal` 根节点读不了 —— 拿到你地址的人**无法枚举有哪些牌局**，必须先知道那 12 个字符 |

**规则不校验"你是谁"**，它只限制写入的形态。这是刻意的：玩家不登录、不装 App，扫完就走。

### 3. 在 BGTools 里填上

工具页 → 发身份 → 配好板子 → **扫码发牌** → 把第 1 步那条 URL 粘进去 → **连接测试**。

测试通过后地址就记住了，以后不会再问。

> 连接测试会**故意往库里写一条几十字节的废记录**：只读一下测不出你的写规则有没有发布对，而那个错误如果留到现场，第一个撞上的会是某位玩家的手机 —— 那时二维码已经举起来了。宁可在这里就报出来。

## 三、每局怎么走

1. 配好板子 → 点扫码发牌 → 屏幕上出二维码和「已领 X / N」
2. 各人扫码，**顺序随便**，扫到即看到身份
3. 你自己的那张点「我也领一张」
4. 有人手机刷新 / 重扫 → 看到的还是同一张
5. 扫的人超过牌数 → 多出来的那台会看到"已领完"

牌堆每局重洗（种子是新的 `crypto` 随机值），"第一个扫的总是狼"不会发生。

## 四、隐私边界

- **数据库里不存在"谁是什么"**：只有一串排队时间戳（和内容型游戏的词池）。牌堆配方走二维码
- 所以拿到你数据库地址的人，看到的是一堆时间戳；要对上必须**在场扫到那张码**。而且他连"有哪些局"都列不出来 —— 根节点不可读
- 只读能看到词池里有哪些词，但不知道谁拿哪个、也不知道配比
- 玩家手机上只存 `牌局 id → 自己的 id`（最近 20 局），身份是当场算出来的，不落盘

## 五、容量与清理

一局约 235 字节，1 GB 大约能存四百万局，容量不构成约束。

规则**刻意不给删除权限** —— 否则任何拿到地址的人都能删掉别人正在进行的那一局。真要清，去控制台手动删 `bgtools/deal` 节点。

## 七、不想配怎么办

用轮传发牌，功能完整、零配置、不用网络。扫码只是快一点，**不是主路**。没配后端、断网、后端报错，都只让「扫码发牌」这一个按钮走不通。
